# 自适应提前整理阈值算法方案（初稿）

**状态：2026-10-21讨论稿，未实现、未部署，不改变现有配置。** 本文把“读取历史轨迹→预测未来使用→随机扰动模拟→比较候选阈值→给出建议”整理成可审查的算法方案。自动生效权限、参数和正式接线须另行确认；本文不授权在线试验，也不替代现行[07 §6.3、§8.1](07-scheduler-notebook-noting-compaction-redesign.md)的配置与运行契约。

## 1. 目标与唯一决策变量

对每个Conversation，在其原生模型、Provider、推理设置及工作阶段下，估计**提前Idle联合整理的上下文阈值T**。费用是评价函数，T是唯一被优化的决策变量；delay、模型、全局资格、Force线和原生压缩策略在一轮比较中固定，不另建“开不开Noting”的二元预测目标。

候选集必须包含`T=∞`，表示Idle不提前整理，让既有Force／原生流程接管。它不表示关闭全局Noting、取消Conversation参与、禁止手动整理或跳过原生压缩。有限T只决定在现行Idle条件满足时是否可以提前进入联合流程，不能突破Force空间检查、来源资格、Profile／route验证、compression fence或admission去重。

算法输出为“建议阈值或近优区间＋与现状和∞的费用差＋适用条件与未知项”，也允许“证据不足，保持原值”。不承诺数据越多必然更省，不把情景最低点称为现实唯一最优值。

### 1.1 当前会话的判断与小规模条件预测

**结论：建议开，以96K作为初始建议；128K仍有经济收益，但不作为本轮首选。** K按1024计。建议只针对Idle提前联合整理，原生Force／auto不变；没有实际改动任何配置。

先核现实事件：从昨晚约21:38手动Compact到今天13:05，共18个普通主Turn、46次API、8个cold-first。假设Noting昨晚复用热父成功，并补算Notebook提前载入费用，API等价预算为“不整理约35.02元；整理及维护约22.85元”，净约12.17元；参数情景净10.29～12.40元。即使不给中午异常两个Turn计算历史缩短收益，仍估计净6.50～8.14元。这支持本会话提前整理值得保留，但不单凭这次手动事件定位最优T。

再用已有50Turn／145API数值轨迹构造预测：18个cold-first中形成17个闭合批次，严格排除跨压缩、未归因跳变、Notebook载入及异常循环后留12个完整使用批次。每批真实增长中位1427、均值4489、最大34261 token，平均约6.58次API；保留冷首请求后全部热Turn及内部API，不当作每Turn全冷。修正口径另加入两个明确作假设修正的批次，共14个；不声称筛选后的短窗口无偏。

小规模模拟在各结构情景中使用8个随机种子，先预热300、再比较共同1200份外部使用批次；两个筛选后相邻批次为抽样块，材料增长整体施加15%对数正态扰动。筛选后相邻可能跨过排除区间，因此这是经验块近似，不是原始连续过程的无偏重建。所有候选使用同样外部工作，维护不增加分母；另用4800批次核末态影响。以下中央情景均包含正常冷热API、Note、Compact及压缩后首父请求重新冷预填费用：

这是**预测假设下的可比预算，不是用户将来一定会发生的100次使用、实账或置信区间**。相同费用归一仅用于比较T。中央低点为80K；96K多约2.9%费用、少约24%维护，相对现值128K约少10%费用。底座增至65K、Noting工作量上升等联合情景下，96K成为费用低点；它在本轮其余列明情景中约高于各自最低点0～6.1%。选择96K还包含避免过密维护的保守判断，不声称其质量已证明优于80K，也不冒称它是单纯费用意义下的全情景最优。

中央使用K3公开API等价价格：普通输入20、缓存读2、输出100元／百万token，不是Kimi Coding订阅扣额。维护以一次成功11API Noting的形状、热父读取、一次完整Compaction的约2.19元代估为基准；reset取含约5K Notebook的53K。冷首请求统一只保留2048根缓存、热请求保留经验fresh suffix形状，属于条件标准化而非精确重放实际cache。结构敏感性分别及组合考察reset48／60／65K、Noting工作量0.75／1.5倍、首父输入部分／全部miss、native/provider比例0.9／1.12、delay60秒、有界尾部或零尾部、严格／修正轨迹。15种情景下96K相对∞的模拟费用优势约21%～34%，是所列假设情景的跨度，不能当作现实概率或严格上下界。

**限制决定建议的强度。** 逐请求输入使用provider token；阈值本应使用正式native测量，尚无完整配对校准。此次只是按比例情景近似，不能直接宣称所有阈值触发点精确重放。原生Force先Note、auto另行Compact的顺序保留，但Note按成功且及时完成近似；异步耗时、失败／忙碌admission、Snapshot延后载入、Notebook长期增长和压缩输入长度函数尚未拟合。一次成功Note及一次完整Compaction不是总体分布；15%扰动、结构参数亦不是数据学得的方差。正常外部工作及调用形状固定，额外检索、返工和隐性质量损失不可识别，未由模拟证明可忽略。§7是将来正式算法应达到的要求，本次条件脚本未实现其全部状态与质量模型。

独立复核确认费用与共同工作量分母无足以推翻中央排序的重复项；发现Noting首次读取最终Assistant尾部少计fresh差额，已补计。53K在脚本中表示压缩完成底座的情景值，不是精确观测的首次正常prompt；样本只能约束其大致范围。容量检查没有覆盖Noting全部suffix／输出预留，因此不作为runtime合法性证明。

恢复费用敏感性也影响“是否调整现值”：在大底座、较贵维护、修正增长的联合情景中，96K相对128K只少约11元／100批次，同时多约6.4次维护；每次额外维护若新增约1.8元找回／返工费用，就可能抵消优势。这是未知成本的盈亏平衡预算，不是已观测的检索费。

因此，当前回答是“经济性上值得开，初始推荐96K”，不是“已经证明96K长期最优”。延续现有128K是承担较少维护的保守选择，也比直接关闭更符合当前证据；若以后观测到新增恢复／质量成本，应重新估计而不固守本轮数字。

## 2. 两种问题分开回答

**有限历史事件预算**：共同起点是一次指定事件，截止是同一条最后普通请求；只比较这个区间的费用。可以明确假设“昨晚Noting热父成功”，用恢复任务的usage重分类，而不重复加入实际冷补跑和已排除的50call事故。窗口末未达到维护条件，就不能为了补齐周期而虚构一笔维护费。该问题回答“这次事件在指定假设下净省多少”。

**长期阈值策略**：比较正常使用、每次维护及其后果不断重复后的总费用。不能把有限事件净收益直接当作T的训练标签，也不能拿不同正常工作量、不同截止或少付一笔周期末维护的两条线比较。T=∞仍可能支付Force Noting及原生压缩，具体按现行状态转换发生。

本轮旧“每Turn恒冷／固定30K增长”模拟、混合窗口得出的百分比不作为当前推荐依据。最新固定历史事件计算与独立复核仅用来校验费用账本：Notebook在成功路线提前出现的输入费要补上；未Noting路线只移除实际已经出现的Notebook；同一维护只计一次。它们尚不能识别完整长期过程。

## 3. 数据契约：上下文存量与费用流量分开

记录以Profile＋稳定Conversation归属，Session仅辅助定位。下表是拟议分析输入，不新增模型可见字段、不改原数据库ownership；存储形式与保留期留到实施时确认。优先复用已有usage、正式测量和事件元数据，缺失记未知，不用正文猜出精确token。

| 数据对象 | 最小信息与用途 | 不得混淆 |
|---|---|---|
| 请求 | 顺序／时间、所属Turn、主任务／Noting／压缩／检索／重试类别，实际路由及版本 | 一次Turn可有多次API；重试不能算新增正常工作 |
| 计费usage | 总输入、普通输入、cache read、各TTL cache write、输出及reasoning口径、单位／来源 | 总输入含cache时先分类；reasoning若已含于output不得再加 |
| 原生占用测量 | native measured context、取样接缝／时刻、resolved window、auto threshold、Force能力结果 | 这是触发依据；不能拿累计usage替代 |
| Provider prompt | 每次请求实际input、封装／协议／工具版本、最后主请求输入 | 与native测量可有系统偏差，不默认同一个量 |
| 缓存观察 | 实际cache分类、可用时的TTL／prefix变更原因、间隔 | 时间间隔只作解释变量，不证明命中；cold是观测标签 |
| 外部工作 | 用户／Reminder等来源标签、到达时间、正常工作批次、阶段 | 有效工作完成不能仅凭API次数断言 |
| 维护事件 | 手动／Idle／Force／auto来源，admission、开始／结束、成功／失败／no-op、实际usage、压缩边界与Notebook载入时刻 | Noting提交与压缩成功是不同事件，失败费用不能消失 |
| 维护后状态 | 第一正常prompt、Notebook／Framework大小及计数方法、后续检索和返工、延迟 | 压缩后底座与阈值、Notebook大小可能相关，不能固定独立reset |
| 路径／异常标签 | 压缩、rewind、branch、模型／协议／root／工具变更、部署、异常循环、人工修复 | 负prompt跳变不直接当负业务增长；正跳变也可能是封装变化 |

### 3.1 冷启动批次及真实增长

一个使用批次可包含首次较冷请求、多个热Turn和多次内部API。冷定义保留当前统计标签的来源，例如“首请求至少80%未缓存”；同时保留连续cache比例，避免把这条分析标签变成运行门禁。相邻冷启动之间可以有Reminder，其输入影响Conversation存量，应标记来源而非悄悄删掉。

同一路由、封装与有效路径段内，批次间增长可用相邻首次实际prompt之差作观测；批次内部保留每次输入变化、最后输入与最终Assistant尾部。**不累加所有请求的input/output来表示context增长**：历史被反复读取，usage是流量。最终Assistant从生成变成下一次输入时可能尚未缓存，不能提前当热；下条尚未到达的用户输入不能出现在本次Noting父前缀里。

现有冷启动资料只有少量有效区间，部署／调试期的选择偏差明显。压缩、rewind、协议变化等段先切开并归因，不把负差截零后宣称得到无偏增长分布；有符号原始序列和排除理由都保留。无法归因的断点进入独立情景，不混入普通增长拟合。

### 3.2 归一与对账

分别保留原始native与provider量，以同一正式接缝的配对样本估计偏移／范围；无稳定配对时，只能给候选native阈值对应的provider费用范围，不做伪精确映射。模型、API模式、工具／root版本变化后分层或重新校准，不把Kimi tokenizer代理、字符数、OpenAI token数互相替换。

逐类对齐请求日志与累计usage，检验漏记、重复、跨任务归属和截断；总输入应等于普通＋cache read＋各类write，具体字段按Provider原生契约归一。累计账本只能校验覆盖，不能恢复丢失的逐请求缓存路径。异常缺usage保留缺口或成本区间，不能计为零。

## 4. 预测模型：只估计数据能支持的部分

预测对象是未来**外部工作轨迹**：批次到达与间隔、阶段、正常工作材料增长、批次内热续聊及调用形状。历史cold批次是统计分段，不强制每个候选产生相同cache miss；若维护使prefix失效，这是该候选的成本，不能因此增加它的正常工作分母。

初版优先使用简单分层统计和连续块重采样，不额外调用模型做预测。按同Conversation近期阶段估计；必要时向同模型／Provider／相似阶段的聚合先验收缩，并明确共享范围。长停用、集中重任务、Reminder介入等采用独立阶段或混合情景，不能把全历史一次平均。

保留“增长—调用数—输出—间隔—冷热”的联合关系。Bootstrap以连续使用块／完整工作段抽样，块内保留多个Turn和内部API，不能独立抽每个字段或每个请求来打散相关性；块长及阶段占比做敏感性，样本过少就用少量解释性轨迹。压缩与异常在原位置作为事件或条件转移，不能随普通请求随机拼贴；历史用户请求类别无法识别时保留未知标签。

维护响应另建条件模型：给定整理前上下文、待整理新材料、Notebook大小、阶段、路由，预测Noting费用、压缩费用与后续状态的联合范围。**目前Noting及完整Compaction有效样本各少至一次，无法拟合可信方差、平方后缀律或阈值因果曲线。** 先采用明确的费用／缩短量／Notebook区间与多种函数形状，不能把人为噪声当学得的分布。

信息分三类输出：可观测统计；假设下的结构参数；不可识别的隐性质量损失。后两类不得由增加模拟次数变成“已证实”。

## 5. 目标式与候选比较

记D为截至当前的证据，θ为预测／维护／缓存等模型参数与结构情景，ω为给定θ下未来外部使用轨迹。π_T只改变Idle阈值，全部候选从同一个当前状态起步；其它权限、安全规则与原生参数一致。

长期费用目标可写为：

```text
J(T; θ) = limsup Eθ[C_total(π_T, 前K份正常外部工作)] / K
         K→∞
C_total = 正常模型费 + Noting费 + Compaction费
        + 可计费检索/额外调用 + 失败重试/恢复/返工费
```

K使用预先定义、所有候选共同的正常外部工作批次数或等量有效工作。一次检索追加三次API、一次维护重试，增加费用而不增加K；不能用每个策略自己的模型调用数作分母。批次定义按外部使用分段固定，不能把策略引发的cache miss包装成新的“正常cold批次”。用户阶段变化时报告分阶段结果，不混成一个永恒常数。

有限预测窗口中，所有候选处理同一段外部工作并使用相同截止。对完整更新周期，采用`总周期费用／总正常工作量`，不平均逐周期单价；只有状态确实满足更新过程条件时才使用Renewal reward。候选周期长短不同时不能只截取各自最便宜的前半周期。

长期求解应覆盖多次完整维护及其后续使用，并用共同外部工作前缀和更长窗口核验尾部偏差。截止时已受理的维护／重试成本完整计入；未完成周期保留末态与后续价值范围，不能无依据强制所有策略在截止点再维护一次。若不足以控制末态差，只给有限窗口结果，不冒称长期目标已求解。

质量、延迟、容量与既有契约是约束；已测的额外恢复费用进入C_total，漏记事实等潜在损失另外给情景或容忍预算。没有证据时不能把潜在损失设为零，也不能假定它必随阈值单调变化。只有成本与质量证据均支持的候选才进入建议集；否则保持原值或报告条件建议。

## 6. 逐请求成本账本

每条候选轨迹均从请求序列形成账本，分类互斥、按所选计费口径计一次：

```text
C_api = (I_regular*p_regular + I_read*p_read
        + ΣTTL I_write,TTL*p_write,TTL + O*p_output) / 1,000,000
```

| 部分 | 必须计入及去重规则 |
|---|---|
| 正常批次 | 首次冷／部分冷输入、每个热Turn和内部API的cached输入、新suffix与输出；热费用低但不为零 |
| Noting | 已处理父prefix的实际或情景命中，首次未缓存Assistant尾部、任务／工具suffix、后续每次请求、输出；父prefix已付写入是起点前成本时不重复加入 |
| Compaction | 实际每次辅助请求／输出、失败重试／no-op；它与Noting可能不同步，不能永远合并为一个固定终点 |
| Notebook | 完成后真正载入父请求才开始付输入费；以后每次读取均计。提前成功路线须补早期载入费，未Noting路线只移除其实际已载入部分 |
| 检索／恢复 | 工具收费、返回内容在后续请求的输入、追加模型输出／多次冷读、再维护／返工；同一请求先计完整账单，再标归因，不重复加一份“检索模型费” |
| 失败与异常 | 已发生请求仍付费；重试是否获准、去重与资源释放沿原生流程；保留常态／异常剔收益两个视图 |

API等价价格与真实订阅扣额分开；精确模型、服务档、币种和价格版本进入分析收据。GPT本轮按约256K同价窗口情景，不引入阶梯计价。普通输入价与缓存写入总价不是可叠加项目；缺write细分时报告明确的分类情景，不能称实账或严格上下界。不同币种不直接合计，换路由的token工作量不能视为不变。

缓存模拟使用前缀状态、间隔、TTL及协议变化条件；无法识别时采用多种相关冷热路径，不只给每次请求独立抛硬币。热父假设限定到最新已处理输入；尾部首次按fresh、后续可命中；首请求miss后续变热与整任务全冷是不同情景。反事实状态改变时不能未经说明照搬实际cache事件。

### 6.1 简化公式：用于定性分析和算法设计

**简化公式有价值：它帮助理解因果方向、寻找候选范围、检查模拟结果是否反常；它只用于定性分析，不能替代实际轨迹上的阈值求解。** 不因公式无法精确预测本会话，就否定其研究和调优价值。

先看一次整理的回本条件。若整理使后续第i次请求少读取Dᵢ个历史token，该部分输入的边际单价为pᵢ，则近似：

```text
正常读取毛节省 ≈ Σᵢ Dᵢ × pᵢ
净收益 ≈ 正常读取毛节省 − Noting费 − Compaction费
        − 新增Notebook输入费 − 新增冷预填充费 − 检索/返工等额外费用
```

pᵢ按真实冷热分类取值，价格单位须统一到元/token；热请求的pᵢ较低但不为零。若D近似固定、只看n次冷启动，则回本次数约为`维护及额外费用 / (D × 冷输入单价)`。这解释为什么删去较多历史、后续重复读取较多时，更容易收回维护费。D随时间或策略变化时，应回到逐请求求和，不能把固定D外推到跨越多次原生压缩的区间。

再看一个理想长期周期：R为整理后底座，T为整理阈值，每份正常外部工作平均使上下文增长g，整理固定成本为H；令a为每份外部工作中，保留一个历史token带来的总边际读取费，包含首次冷读与该批所有热读。假设线性均匀增长、阈值到达即整理、底座不变、缓存形状不变、无额外恢复成本，则：

```text
每份正常工作的费用 C(T) ≈ C₀ + a × (R+T)/2 + H × g/(T−R)
理想驻点              T* ≈ R + √(2Hg/a)，T > R
```

C₀包含此简化条件下与T无关的费用。平方根式说明：维护成本H较高，倾向晚整理；每份工作增长g较小，或单位新增材料被冷／热反复读取的费用a较高，倾向早整理。**“每次增长少、重复使用多，越值得早压缩”是有用的定性判断。** 但如果每批增长、冷热形状不变，只把同样批次压缩到更短日历时间，读费与维护次数会同比加快，最优token阈值未必改变；频率通过TTL、冷启动密度或工作阶段改变a/g时，才会改变费用平衡。

实际存在突发大批次、Idle等待、Force先Noting后auto压缩、Notebook增长、维护随待整理材料变化、缓存失效、质量和检索反馈。因此公式不用于直接写配置、不报告精确最优token数，也不将公式给出的收益比例当实测。Monte Carlo应保留这些事件和关联；公式提供方向参照，出现相反结果时回查假设和账本，而非强迫模拟符合公式。

## 7. 双层预测与Monte Carlo步骤

1. **固定评估口径。** 记录数据截止、当前路径／路由、native测量、原阈值和权限；定义共同外部工作量、阶段、固定delay及候选范围，显式加入原值和∞。候选须适配当前原生窗口与Force能力，资格失败时只报告，不尝试调大窗口或改安全线。
2. **外层构造θ情景。** 对增长／间隔过程、阶段比例、测量映射、维护曲线、Notebook大小、缓存行为及恢复费用保留参数不确定性；有足够连续块才能bootstrap参数，单样本维护采用披露的结构区间。没有可信后验的情景权重不命名为现实概率。
3. **内层生成ω轨迹。** 在给定θ下生成同一未来外部工作、到达时序与阶段；同一ω供全部T使用，以共同随机数减少比较噪声。策略造成的维护、检索、retry等是内生后果，不能强迫其调用数与实际历史完全相同；仅理想账本校验情景可以固定这些后果。
4. **按正式事件顺序推进候选。** 正常请求→使用实际接缝的测量→Main结束／Idle等待→新Main到来取消等待→符合T时联合入口；Force和auto／手动入口独立照常。模拟Noting与压缩分别成功／失败、Snapshot载入及后续cache与底座，继承admission区间去重；不得在同一未压缩区间凭失败自动无限补起Noting。
5. **累计完整账本与末态。** 每个候选支付所有普通／热请求、维护与后续费用，记录K及尚未结清状态；用更长共同轨迹与完整周期核验有限截断。过窗或无法映射到原生测量的路径标不可用／证据不足，不能继续假装合法调用并把它们当便宜样本。
6. **分层汇总。** 内层给随机使用变动下的费用分布及Monte Carlo误差；外层给参数／结构变化后的排名、费用差、最大不利情景及恢复预算。模拟次数仅缩小数值积分误差，不增加真实样本或消除质量未知项。
7. **选稳健近优线。** 使用事先声明的近优容差与最小有意义改善，而非逐token追最小值。优先保留仍在稳健近优集合内的现值；改动候选须对现值和∞都有清楚解释，且在可信不利情景下不出现不可接受退化。多个候选不可分时返回区间，按少变更、既有行为和维护负担选择起点，不假装精确识别最优值。
8. **输出审计收据。** 包含建议／未建议原因、候选表、数据量与时间、缺口、假设、价格／模型版本、共同工作量、冷热与维护分项、质量盈亏平衡预算、未覆盖路径、随机种子与失效条件。所有审计标识留在分析层，不注入模型Prompt。

简单平方根公式只能解释“增长、历史边际读取费、维护固定成本”如何影响方向，不作正式求解器。固定每批次增长与冷热形状时，单纯增加日历频率会同时加快读费与维护，未必改变最优token阈值；频率改变伴随每批增长、TTL命中或阶段变化，才重新估计这些量。

## 8. 更新、回退与实现边界

**第一阶段只做影子建议。** 在既有事件后按需重估，不新增轮询器、调度器、Main admission gate、Agent Loop或独立模型路由。采集／分析失败不阻断正常Turn、Noting、压缩或Scheduler。数据与建议归属目标Profile／Conversation，不借启动Profile；非eligible与未启用路径保持原生。

当前07规定Idle默认关闭；开启时threshold为正整数、delay非负。`∞`只是算法候选，不能把无穷、0、负数或null直接塞进现有启用状态。未来怎样把建议映射为Conversation有效阈值、Profile配置或现有Idle子开关，需要单独定案；不得借∞关闭全局Noting或Scheduler，也不修改原生自动压缩互斥规则。

后续若授权自动生效，仍需确认更新接缝、作用域、人工固定值优先级、变化幅度、冷却／滞回与回退规则。原则是：沿原生空闲／构造恢复等正式边界更新，已受理任务冻结其原值和父状态；不在Main中途改root、toolset、历史、记忆或cache前缀，不触发离线重建。强制安全线照常优先，禁止为追求经济阈值修改能力检查或权限。

数据少或漂移时保留已确认旧阈值，输出证据不足；没有旧值时不能自行选一个所谓最优值上线。模型／协议／工具包装、压缩残留、冷热分布或阶段明显变化后降低旧数据权重、重做影子评估；需足够新证据才解除保守状态。已经获得授权的自动策略若出现恢复成本／质量异常，应在预定边界回到先前已确认配置，不回滚历史、Snapshot或生产数据库；回退权限亦须提前明确。

只运行当前阈值，只能校准该策略的真实过程，观察不到其它T的现实反事实。应在执行前保存影子预测，之后按原策略自然产生的新批次／完整维护校准费用、cache、增长与reset残差；时间分割回测不能用未来数据预测过去。**不未经授权在线A/B，也不把没有探索当成已学到阈值因果收益。** 若以后需要主动对比，须另获用户授权并明确范围、质量观察与停止条件。

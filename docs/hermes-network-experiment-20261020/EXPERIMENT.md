# 上线后的精简网络实验

**先完成第一板块并上线。** 本轮只回答足以决定下一步的几个问题，不做全面网络论文。目标 10–15 分钟，20 分钟硬停止；到第 15 分钟不再新开分支。结果少时逐样本报告，不宣称长期 p95。

## 1. 准备尽量并入已有发布窗口

同一手机、Chrome、位置、前台亮屏。不启用 VPN/显式代理、不用 USB 反向供网；Wi-Fi 轮确认手机没有自动旁路到移动数据。保留既有登录，不为测速清 Cookie。记录实际 Web/Gateway/前端版本，第一板块未通过的项目单列。

复用原 phone_observer.py，只补现有 CDP 事件的元数据：
- request/headers/data/finish/failed 单调时间；
- protocol、remoteIPAddress/Port、connectionId/Reused、response.timing；
- 缓存来源、Content-Encoding/Length、Content-Type；
- 状态码/redirect hop，必要时 CF-Ray、CF-Cache-Status、Age。
缺字段填 unknown，不能猜 0/false。不要收 Cookie、token、完整私密查询、POST 或 WS 内容。

如果已有 ADB/日志可用，自动采这些字段；本轮不要为此安装庞大工具链。可选短时 NetLog、ss -ti 只在已有条件下辅助，非必做。

用 probes/make_assets.py 生成固定 8 KiB/64 KiB/1 MiB 文件，将 probe.html 与文件放入临时受保护诊断目录。可并入第一板块 Caddy 发布，避免额外 reload。
- 同 origin、有效 TLS、沿用现有认证；只暴露生成目录，无目录浏览。
- .bin 用 application/octet-stream，准确长度，private/no-store，本轮不压缩，不让浏览器或 CDN HIT 替代网络。
- 页面不会自动请求；默认只有 8 KiB+64 KiB，每文件 30 秒 JS 主动中止上限。
- 中止保留已收 bytes，标 aborted_timeout；不能称为 TCP 30 秒超时。浏览器挂起可能使计时器延后。
- 私人 API/图片不因实验进入公开缓存，不修改认证边界。

若准备新诊断设施超过约 3–5 分钟，停止扩设施，先用已有 CDP 对真实 UI 做同机 A/B。此时只能判断实际体验和应用时序，不能声称已排除字节载荷差异。基础可观察性在第一板块准备好，用户实际操作仍控制在短时段。

## 2. 必做只需两轮

| 步骤 | 操作 | 记录 |
|---|---|---|
| A：蜂窝直连 | Wi-Fi 关闭，确认换网后新请求；探针默认 8/64 KiB 一轮 | 逐个请求 headers/body/total/已收量/状态/最长观察停顿 |
| A 的真实 UI | 做一次最痛的动作，例如打开指定历史会话或切回前台 | 首次文字可读、bootstrap/WS/ready/历史阶段、关键 bytes；最多观察 30 秒，未就绪记 >30 s |
| B：同机 Wi-Fi | 确认实际新网络与请求，再做相同探针和同一 UI 动作 | 同样记录，保持数据窗口和登录条件 |
| 必要时 A2 | 只有蜂窝刚好很快，或 A/B 差异不清，才回蜂窝复核一次异常项 | 换网过渡单列，不默认增加所有轮次 |

两輪默认固定下载总共只有 144 KiB，另加诊断页、协议和真实 UI 流量。若 64 KiB 已明显慢/中止，无需再传 1 MiB。**仅当小下载都很快、仍怀疑持续传输时**，允许一次大样本；仍 30 秒中止，不为了等完整结果拖一分钟。

真实 UI 若因为第一板块 refs fallback 仍带大图，记录这个事实，不能把它当成纯线路复测。不要刻意触发长模型任务；只读操作已能回答主体问题。

## 3. 每轮必填字段只有这些

1. 时间、蜂窝/Wi-Fi、SIM/宽带运营商、4G/5G；未知保留未知。
2. 无 VPN/显式代理、同手机前台、入口主机名、第一板块版本。
3. 实际 remote IP、地址族、协议、连接复用；CDP 无法得到则写缺口。
4. 服务器看到的相应公网出口地址，及已有工具能快速查到的 ASN；不为 ASN 拖延测试。
5. 8/64 KiB 和真实 UI 的逐样本阶段时间、字节、状态，缓存/鉴权是否影响。
6. 橙云如果测过，补真实 colo/CF-Ray；IP 地理库的“美国”不能替代实际 colo。

conditions.example.json 是完整可选模板，不必把每个高级字段填满。DNS 的 A/AAAA 与浏览器实际连接不一致时，以实际连接判断该请求；需要时才补地址选择调查。

服务端可信客户端地址只按现有受信代理规则读取，不能无条件信任任意 CF-Connecting-IP。报告原始对端与可信转发地址的区别。

## 4. Cloudflare 降为可选，不再四格测试

用户 Wi-Fi 已有代理更慢经验，普通 Cloudflare 也不保证更近入口，因此优先级低于上述直连 A/B。

仅当**已经有**受保护、TLS/源站身份正确、回同一首尔服务的普通橙云入口，且预算还剩时间，才对蜂窝补一次相同小探针。必要时回直连一次复核。没有现成入口，或新增准备超过约 2 分钟，本轮跳过；不切主域橙灰、不重建 Tunnel、不买 Argo。

- 灰云对照必须是真正指向公开首尔源站的 DNS-only A/AAAA。把 Tunnel CNAME 改灰不等于绕过 Tunnel 直达源站。
- 普通橙云是手机→Cloudflare→公开 HTTPS 源站；Tunnel 则由源站 cloudflared 主动建连接，Cloudflare 经隧道访问源站。
- 动态/鉴权/诊断内容绕过共享缓存；静态 HIT 不与直连实时 API 作为同内容性能结论。
- 记录自然协商 h2/h3、IPv4/v6 和 actual edge。不同主机名也改变连接池和 Cookie，不能冒充纯协议单变量。
- 橙云若更慢/无可靠收益，本轮即停止；一次快只算候选，不能直接切生产或宣布解决流恢复。

若直连观测明确指向可现成验证的 IPv4/v6 差异，可以把剩余时间用于**那一个**有根据的对照；不用同时跑 h1/h2、4G/5G、MTU、BBR、DNS 的全排列。

## 5. 如何决定下一步

| 结果 | 结论/下一步 |
|---|---|
| 8 KiB 也慢，建连/headers 占主导 | 查实际地址族、DNS/连接/认证；大 JSON 优化不能解决全部等待 |
| 小响应快，64 KiB 或大响应正文持续停顿 | 路径/连接的持续传输是重点；有现成 ss/NetLog 时关联重传、ACK 停顿 |
| 固定下载快，真实 API 慢 | 查已压缩 bytes、图片 fallback、应用处理/反代写出/鉴权；不能直接指定数据库根因 |
| API 单独快，完整 UI 慢 | 查请求竞争、重复取消、恢复串行和渲染，第二板块聚焦应用编排 |
| 优化后文字快，原图仍慢 | 证明确已解除历史阻塞；第二板块做完整媒体资产化/缩略图和按需质量 |
| 直连持续差，现成橙云明显更好 | 仅列为候选，后续先验真实鉴权/聊天流/恢复，才决定入口切换 |
| 两轮都快 | 标“本轮未复现”，保留轻量采集，不能宣称线路长期正常 |

路由探测可留后续有针对性的排查：本轮不要求 traceroute/MTR、不 root 手机。中间节点 ICMP 丢包不等于转发丢包，去回程不同，ASN/地理库也不能还原完整物理路径。

## 6. 一页结果就够

回交：
- 第一板块实际部署与未完成项，新的关键 bytes、图片 fallback。
- 蜂窝和 Wi-Fi 各一行的运营商/出口/remote IP/协议，以及每次小下载/真实 UI 的阶段时间。
- 状态分开：成功、网络失败、手动取消、JS 超时中止、采集未完成。
- 主要剩余瓶颈：握手/认证、持续正文、应用过量读取、恢复串行或证据不足。
- 尝试了哪个网络改善；没有安全现成候选时明确“未试”，不能改写成无效。
- 是否值得继续试一个有针对性的公网入口/地址族方案；第二板块的输入事实。

20 分钟停止。不要为了所谓“彻底查清每个运营商内部节点”阻塞改善体验。
